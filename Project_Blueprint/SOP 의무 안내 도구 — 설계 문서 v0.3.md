# SOP 의무 안내 도구 — 설계 문서 v0.3

Nov 10, 2026 · @김희준

> **v0.3 변경 요약:** (1) 알림은 앱이 직접 보내지 않고 Outlook·구글 캘린더가 맡는다. 앱은 일정을 캘린더에 넣기 쉽게 만든다. (2) 할 일 이행 기록과 이력 조회를 범위에 넣는다 (서식 작성은 계속 제외). (3) 데이터를 브라우저 저장소에 더해 PC·공유 폴더의 파일로 자동 저장하고, PWA로 설치·오프라인 실행을 지원한다.

## 목적과 범위

첫 버전은 회사 SOP에서 작성·기록·보고 의무를 뽑아 회사가 확정하게 하고, 이벤트가 생기면 할 일과 기한을 안내하는 도구다. 서식을 앱 안에서 작성하는 기능은 넣지 않는다.

- **해결할 문제:** 의무가 SOP 곳곳에 흩어져 있어 기억에 의존하면 놓친다. 컬프 공통 SOP 23개에서만 107건이 나왔고, 그중 언제 생길지 모르는 수시 이벤트형이 42건으로 가장 많다.
- **대상:** 비GLP CRO, 동물용 임상시험 실시기관처럼 eQMS를 들이기 어려운 소규모 기관. 첫 사용자는 컬프.
- **원칙:** 안내 목록은 참고용이며 SOP 원문이 우선한다. 목록은 회사가 확정한 버전만 안내에 쓴다. 무료로 배포하므로 AI(LLM) 호출과 서버 운영비가 없어야 하고, 모든 처리는 사용자 브라우저 안에서 한다.

| 첫 버전에 포함 | 첫 버전에서 제외 |
| --- | --- |
| SOP 업로드 (HWPX, DOCX, PDF) | 서식 작성·전자서명 (전자기록이 시험기초자료가 되면 감사추적 요건이 생김) |
| 규칙 기반 의무 초안 (기본 템플릿 연결) + 근거 조항 원문 | AI(LLM) 추출, 서버·DB, 여러 사람이 같은 데이터를 실시간 공유 |
| 검토·수정·확정 화면 | 메일·메신저 알림, 앱을 닫은 상태에서 앱이 직접 띄우는 알람 (서버나 설치형 프로그램이 필요) |
| 이벤트 입력 → 할 일·기한 목록 | 모바일 앱 |
| 시험 단계별 체크리스트 | 법령 개정 자동 추적 |
| 정기·만료 캘린더 + 캘린더 연동 알림 (Outlook·구글) | 스캔 PDF의 OCR |
| 할 일 이행 기록, 이력 조회, 엑셀 내보내기 | 캘린더에서 완료 처리한 내용을 앱으로 되가져오기 |
| PC·공유 폴더 파일 자동 저장, PWA 설치·오프라인 실행 |  |
| SOP 개정판 비교 |  |

## 핵심 개념

의무 하나는 "무엇이 생기면(트리거) 무엇을(할 일·서식) 언제까지(기한) 누가(담당) 누구에게(보고처)"로 정의하고, 반드시 근거 조항을 달고 다닌다. 연결의 단위는 SOP가 아니라 이벤트다.

### 의무 유형 4가지

| 유형 | 트리거 | 예시 (컬프 공통 SOP) | 운영 방식 |
| --- | --- | --- | --- |
| 정기 | 달력 반복 | 연 2회 음수 수질검사 (COM/019) | 캘린더 반복 일정 |
| 시험 단계 | 시험의 단계 도달 | 개시 전 시험 개시 점검표 (COM/007) | 시험별 체크리스트, 선행 조건 |
| 수시 이벤트 | 사건 발생 | 중대한 이상반응 → 의뢰자 보고 (COM/008) | 이벤트 입력 시 할 일 생성 |
| 만료 추적 | 날짜 계산 | 검체 보관: 보고서 확정일 + 1년 (COM/011) | 기준일 입력 시 만료일 등록 |

### 연쇄: 한 이벤트가 다음 의무를 부른다

의무는 "다음에 이어지는 의무"를 가질 수 있다. 예: 시험 중 중대한 이상반응(폐사) 발생 시.

1. 시험실시기관장 보고: 즉시
2. 의뢰자 보고, 008-1 이상반응 보고서: 사망·생명위협 24시간, 그 외 48시간 이내
3. 폐사 동물 확인·기록 → 즉시 부검 (불가 시 냉장, 냉동 금지), 023-1 부검 소견 기록지
   1. 검체를 채취하면 → 011-1 검체 관리대장
4. 필요 시 동물실험윤리위원회 보고, 동의서 변경 검토
5. 계획서와 다르게 조치했다면 → 일탈 처리 (001-2), 의뢰자 문서 통보

연쇄는 기본 템플릿에 미리 들어 있고, 규칙이 SOP의 상호참조("KULF/COM/023에 따라")를 보고 회사 고유 연쇄 후보를 더한다. 확정은 사용자가 한다.

### 회사 버전 확정

- 의무마다 상태를 둔다: 초안 → 검토됨 → 확정 (또는 제외).
- 확정된 의무 묶음이 회사 버전 v1이 되고, 안내는 확정 버전만 쓴다.
- SOP 개정판을 올리면 바뀐 조항에 달린 의무만 다시 초안으로 돌아가고, 다시 확정하면 v2가 된다.
- 누가 언제 확정했는지 기록한다. 책임 소재는 확정자에게 있다.

## 데이터 모델

중심 엔터티는 의무(Obligation)이고, 나머지는 의무의 근거(SOP 조항)와 의무의 실행(이벤트·할 일)을 담는다. 담당은 사람이 아니라 직무(시험책임자 등)로 저장하고, 직무와 사람의 연결은 회사 설정에서 한다.

| 엔터티 | 핵심 필드 | 비고 |
| --- | --- | --- |
| Company | 이름, 직무 목록, 직무→사람 연결, 공휴일 달력 | 회사별 설정 |
| SopSet | 회사, 버전 (v1, v2…), 업로드일, 상태 | 개정판 = 새 SopSet |
| Clause | SOP 번호, 조항 경로 (예: COM/008 5.(1)2)), 원문, 해시 | 해시로 개정 전후 변경 감지 |
| Form | 서식 코드 (예: 008-1), 이름, 원본 파일 | SOP 서식 목록에서 추출 |
| EventType | 이벤트 이름 (예: 중대한 이상반응), 입력 항목 (발생 시각, 시험번호, 사망 여부 등) | 이벤트 사전 |
| Obligation | 유형, 트리거 (EventType 또는 반복 규칙 또는 시험 단계), 적용 조건, 할 일, 서식\[\], 기한 규칙, 담당 직무, 보고처\[\], 근거 조항\[\], 신뢰도·플래그, 상태 | 아래 상세 |
| FollowUp | 선행 의무 → 후속 의무, 조건 (예: "폐사인 경우") | 연쇄 |
| Study | 시험번호, 현재 단계, 주요 날짜 (접수일, 종료일, 보고서 확정일 등) | 기한 계산의 기준점 |
| EventInstance | EventType, 시험 (없을 수 있음), 발생 시각, 입력값 | 사용자가 입력 |
| Task | 원천 의무, 마감 시각, 담당자, 상태 (예정·진행·완료·해당 없음), 캘린더 UID | 이벤트·단계·반복 규칙이 만든다 |
| TaskRecord (v0.3 추가) | Task, 완료자, 완료 시각, 입력 시각, 기록한 서식 코드·기록 번호, 메모, "해당 없음" 사유 | 이행 기록. 수정하지 않고 새 기록을 덧붙인다 |

**기본 템플릿 (v0.2 추가):** TemplateObligation은 Obligation과 같은 필드에 "근거 법령 조항"과 "매칭용 키워드·서식 이름 후보"를 더 가진다. 회사 Obligation은 template\_id를 가지며, 템플릿에 없는 회사 고유 의무는 template\_id 없이 추가한다. 첫 템플릿은 검수를 마친 컬프 107건이다. 데이터는 브라우저 IndexedDB에 저장하고, 동시에 사용자가 지정한 PC·공유 폴더의 데이터 파일에 자동 저장한다 (다음 절 "저장과 기록 유지").

### Obligation 상세

- **유형:** 정기 · 시험 단계 · 수시 이벤트 · 만료 추적
- **적용 조건:** 선택 항목 + 직접 입력 (예: "소유자 있는 동물", "병원체 사용 시험"). 이벤트 입력값이나 시험 속성과 대조해 해당 여부를 가른다.
- **기한 규칙:** 구조화된 JSON (다음 절)
- **플래그:** 기한 없음 · 모호한 표현 · 서식 없음 · 담당 없음 · 다른 SOP와 충돌. 플래그가 있는 항목을 검토 화면에서 먼저 보여준다.
- **상태:** 초안 · 검토됨 · 확정 · 제외, 확정자와 확정일
- **수정 방식:** 자유 텍스트는 "할 일" 설명에만 허용한다. 트리거, 기한, 서식, 담당, 보고처는 선택 목록과 정해진 칸으로만 바꾼다. 그래야 기한 계산과 연쇄가 깨지지 않는다.

## 기한 규칙 표현 방식

기한은 "기준 시점 + 오프셋"을 기본으로 하고, SOP 문구가 날짜로 계산되지 않는 경우는 별도 종류로 나눈다. 날짜로 못 바꾸는 문구는 억지로 계산하지 않고 검토 플래그를 단다.

| 종류 | SOP 문구 예 | 규칙 표현 | 계산 결과 |
| --- | --- | --- | --- |
| 상대 | 접수일부터 7일 이내 (COM/004) | anchor: received\_at, offset: +7 day | 접수일 + 7일 |
| 조건부 상대 | 사망·생명위협 24시간, 그 외 48시간 (COM/008) | anchor: event\_at, cases: \[death∨life\_threat → +24 hour, else → +48 hour\] | 발생 시각 + 24h 또는 48h |
| 근무일 | 다음 근무일까지 (COM/005) | anchor: event\_at, offset: +1 business\_day | 공휴일 달력 반영 |
| 즉시 | 즉시, 지체 없이 | anchor: event\_at, offset: 0, soft: true | 발생 시각 (최우선 표시) |
| 선행 조건 | 시험 개시 전, 동물 구입 전 (COM/007) | gate: before study.start | 날짜 없음. 단계 전환을 막음 |
| 반복 | 매월 1·11·21일, 연 2회 (COM/017, 019) | rrule: FREQ=MONTHLY;BYMONTHDAY=1,11,21 | 캘린더 반복 일정 |
| 만료 | 보고서 확정일부터 1년 (COM/011) | anchor: study.report\_finalized\_at, offset: +1 year | 만료일 1건 등록 |
| 미정 | 정기적으로, 매년 초 (COM/016, 003) | undefined, flag: vague | 계산 안 함. 사용자가 날짜를 정해야 확정 가능 |

- **달력일이 기본:** "7일 이내"는 달력일로 계산한다. 근무일 기준은 SOP에 명시된 경우만 쓴다.
- **계획서·계약서 우선:** "계획서에서 정한 기한 이내로 하되 48시간을 넘지 않는다"처럼 시험별 값이 더 짧을 수 있는 규칙은 Study에 재정의 값을 둔다. 결과보고서 30일 기한(COM/004)도 계약서 값이 있으면 그것을 쓴다.
- **기준 시점 목록은 고정:** received\_at, event\_at, study.start, study.end, report\_sent\_at, report\_finalized\_at 등 정해진 이름만 쓴다. 새 기준 시점이 필요하면 사전에 추가한다.

저장 형태 예 (중대한 이상반응의 의뢰자 보고):

```json
{"kind": "relative", "anchor": "event_at",
 "cases": [{"when": {"any": [{"field": "death", "eq": true}, {"field": "life_threat", "eq": true}]},
            "offset": {"value": 24, "unit": "hour"}},
           {"when": "else", "offset": {"value": 48, "unit": "hour"}}],
 "override": "study.protocol_sae_deadline", "override_rule": "min"}
```

조건(`when`)은 자유 문자열이 아니라 이벤트 입력 항목을 가리키는 구조로 쓴다 (`field`·`eq`·`in`, `all`·`any`·`not`, `else`). 판단에 필요한 입력값이 없으면 `else`로 넘어가지 않고 입력을 요구하며, 그동안은 가능한 기한 중 가장 이른 값을 임시 기한으로 보여준다. (v0.3, `src/core/deadline/types.ts`)

## 추출 파이프라인

추출은 AI 없이 규칙으로 하고, 규칙의 목표는 의무를 처음부터 만드는 것이 아니라 기본 템플릿의 각 의무를 회사 SOP 조항·서식에 연결하는 것이다. 실시기관 SOP는 같은 지정규정을 바탕으로 해서 의무의 뼈대가 거의 같다는 점을 이용한다.

1. **파싱:** 파일을 조항 트리(SOP 번호 › 조 › 항 › 호)로 바꾼다. 표는 행 단위로 남겨 "무엇을"과 "주기"가 떨어지지 않게 한다.
   1. HWPX: 브라우저에서 JSZip으로 압축을 풀고 section\*.xml의 문단·표를 읽는다. 컬프 파일로 텍스트 추출 확인함.
   2. DOCX: 같은 방식(zip + XML). PDF: pdf.js로 텍스트 레이어만 (스캔본 제외).
2. **서식 사전:** 목차·서식 목록에서 서식 코드와 이름을 뽑는다 (예: 정규식 `[A-Z]+/[A-Z]+/\d{3}-\d+`). 코드 체계가 다른 회사는 서식 목록 표의 열을 사용자가 지정한다.
3. **템플릿 매칭:** 템플릿 의무마다 키워드·서식 이름 후보로 회사 조항을 찾아 점수순 후보를 붙인다. 예: "이상반응 보고서", "중대한", "24시간" → 회사 SOP의 해당 조항.
4. **기한 패턴 추출:** "N일/시간 이내", "매월", "연 N회", "N년간 보관", "즉시", "지체 없이" 등을 정규식으로 읽어, 회사 값이 템플릿 값과 다르면 회사 값으로 바꾸고 표시한다.
5. **남은 후보 묶기:** 어떤 템플릿에도 연결되지 않은 의무형 문장(키워드 매칭)은 "회사 고유 후보"로 모아 사용자가 채택하거나 버리게 한다. 컬프 SOP 시험에서 키워드만으로는 문장 800개 중 268개가 걸렸다. 템플릿에 매칭된 것을 빼면 이 수가 크게 줄어야 한다.
6. **누락 경고:** 회사 SOP에서 연결할 조항을 찾지 못한 템플릿 의무는 "회사 SOP에 해당 조항 없음"으로 표시한다. 이것이 SOP의 빈틈 점검 기능이 된다.
7. **플래그:** 기한 없음, 모호한 표현("정기적으로", "매년 초"), 서식 없음을 표시한다.

규칙 관리:

- 키워드·정규식은 코드가 아니라 설정 파일(JSON)에 둔다. 표현이 다른 회사를 만나면 코드 수정 없이 패턴만 더한다.
- 매칭 결과에는 항상 근거 조항 원문을 붙인다. 근거 없는 연결은 만들지 않는다.
- 한계: 이 방식은 근거 규정이 같은 실시기관에서만 잘 맞는다. GMP 공장 등 다른 업종은 템플릿을 따로 만들어야 한다.

## 알림, 이행 기록, 저장 (v0.3 추가)

서버가 없는 웹앱은 브라우저 창이 닫혀 있으면 알람을 띄울 수 없다. 그래서 알람은 사용자가 이미 매일 쓰는 캘린더(Outlook·구글)에 맡기고, 앱은 일정을 캘린더에 넣는 과정을 최대한 짧게 만든다.

### 캘린더 연동 알림

| 의무 유형 | 캘린더에 넣는 방식 | 횟수 |
| --- | --- | --- |
| 정기 | 반복 규칙(RRULE)이 든 .ics 한 번 가져오기 | 회사 버전 확정 때 1회. 개정 시 다시 |
| 만료 추적 | 기준일 입력 시 일정 1건 | 기준일마다 |
| 시험 단계 | 시험 생성·단계 전환 시 해당 단계 일정 묶음 | 단계마다 |
| 수시 이벤트 | 이벤트 입력 직후 "캘린더에 추가" 버튼으로 할 일 묶음 추가 | 이벤트마다 |

- **추가 방법 3가지:** (1) .ics 파일 내려받기 (Outlook 데스크톱은 더블클릭으로 추가), (2) "구글 캘린더에 추가" 링크 (일정 내용이 채워진 구글 화면이 열리고 저장만 누름), (3) "Outlook 웹에 추가" 링크. 회사 설정에서 기본 방식을 고른다.
- **알림 시점:** 기한 종류별 기본값을 둔다. 예: 즉시·24시간 기한은 바로 알림, 일 단위 기한은 전날 09:00과 당일 09:00, 만료는 30일 전과 7일 전. 회사 설정에서 바꿀 수 있다. (구글 캘린더는 .ics의 알림 설정을 무시하고 계정 기본 알림을 쓰므로, 구글 사용자에게는 링크 방식을 권한다.)
- **중복 방지:** 할 일마다 고정 UID를 둔다. 같은 일정을 다시 내보내면 새로 생기지 않고 갱신된다.
- **설명란:** 일정 설명에 할 일, 서식 코드, 근거 조항(SOP 번호·조항 경로)을 넣는다. 캘린더만 보고도 무엇을 해야 하는지 알 수 있게 한다.
- **앱을 열었을 때:** 첫 화면에 "기한 지남 / 오늘 / 이번 주" 할 일을 보여준다. 앱이 열려 있는 동안에는 브라우저 알림도 띄운다.
- **한계:** 캘린더에서 완료해도 앱에는 반영되지 않는다. 완료 처리는 앱에서 한다. 사용자가 캘린더에 넣지 않은 일정은 알람이 없다. 그래서 캘린더에 넣지 않은 할 일은 앱 첫 화면에 따로 표시한다.

### 이행 기록

이 도구가 관리하는 것은 "의무를 이행했다는 기록"이다. 서식의 내용(보고서 본문 등)은 지금처럼 종이나 기존 문서로 작성한다. 그래야 앱의 기록이 시험기초자료가 되지 않고 감사추적 요건도 생기지 않는다.

- **완료 처리:** 완료자, 완료 시각, 기록한 서식 코드와 기록 번호(예: "008-1, 2026-003호"), 메모를 남긴다. 해당 없으면 "해당 없음"과 사유를 남긴다.
- **수정 대신 덧붙이기:** 이미 남긴 기록은 고치지 않고 정정 기록을 새로 덧붙인다. 입력 시각은 자동으로 찍는다.
- **이력 조회:** 시험별, 의무(SOP)별, 기간별로 이행 이력을 본다. 기한을 넘겨 완료한 건은 표시한다.
- **내보내기:** 이력을 엑셀로 내보내 내부 점검·실사 준비에 쓴다.
- **한계:** 로그인이 없으므로 완료자 이름은 사용자가 직접 고르는 값이다. 전자서명이 아니며, 공식 기록은 서식 원본이다.

### 저장과 기록 유지

- **브라우저를 닫거나 인터넷이 끊겨도 기록은 그 PC에 남는다.** 사라지는 경우는 브라우저 설정에서 사이트 데이터를 지울 때뿐이다.
- **파일 자동 저장:** Chrome·Edge의 파일 접근 기능(File System Access API)으로, 사용자가 처음 한 번 데이터 파일(예: `컬프_SOP의무.json`)을 정하면 이후 변경 사항을 그 파일에 자동 저장한다. 앱을 다시 열면 그 파일을 읽는다. 브라우저 데이터가 지워져도 파일에서 복구한다.
- **공유 폴더:** 데이터 파일을 공유 폴더에 두면 여러 사람이 같은 데이터를 쓸 수 있다. 다만 동시 편집은 지원하지 않는다. 파일을 열 때 다른 사람이 더 최근에 저장했는지 확인해 경고한다.
- **PWA:** 브라우저에서 "설치"를 누르면 바탕화면 아이콘이 생기고 인터넷 없이도 실행된다. 프로그램 설치 권한이 필요 없다.
- **지원 브라우저:** 파일 자동 저장은 Chrome·Edge에서만 된다. 다른 브라우저에서는 JSON 내보내기·가져오기로 대신한다.

## 화면 흐름

사용자는 한 번 검토·확정하고, 이후에는 이벤트 안내·시험 체크리스트·캘린더만 쓴다. SOP를 개정하면 바뀐 조항만 다시 검토한다.

&#91;embedded content: 화면 흐름 · 확정 전 4단계, 확정 후 3가지 쓰임새\]

개정판은 처음부터 다시 추출하지 않고, 바뀐 조항에 달린 의무만 초안으로 되돌려 검토에 넣는다.

- **업로드:** 파일과 SOP 세트 버전을 지정한다. 파싱 결과(SOP 수, 조항 수, 서식 수)를 바로 보여줘 파싱 실패를 일찍 잡는다.
- **검토:** 왼쪽에 의무 카드, 오른쪽에 근거 조항 원문. 플래그 항목을 먼저 보여주고, 나머지는 SOP 단위로 일괄 승인한다.
- **확정:** 유형별 건수와 남은 플래그 수를 보여준다. 플래그가 남아 있으면 사유를 입력해야 확정된다.
- **홈 (v0.3 추가):** 기한 지남 / 오늘 / 이번 주 할 일, 캘린더에 아직 넣지 않은 할 일.
- **이벤트 안내:** 이벤트를 고르고 입력 항목(발생 시각, 시험번호, 사망 여부 등)을 채우면, 마감 시각순 할 일 목록이 나온다. 후속 의무는 들여쓰기로 보여준다. "캘린더에 추가"로 할 일 묶음을 캘린더에 넣고, 완료 시 이행 기록을 남긴다.
- **이행 이력 (v0.3 추가):** 시험·의무·기간별 이력 조회, 엑셀 내보내기.
- **시험 체크리스트:** 시험을 만들면 단계별 의무가 생긴다. 선행 조건이 남아 있으면 다음 단계로 넘길 때 경고한다.
- **캘린더:** 정기·만료 일정을 보여주고 iCal로 내보낸다.
- **개정 비교:** 추가·삭제·변경된 조항과 그 영향을 받는 의무를 나란히 보여준다.

## 평가 방법

주지표는 재현율(정답 의무 중 추출이 찾은 비율)이다. 빠뜨린 의무는 검토 화면에서도 보이지 않지만, 남는 의무는 사용자가 지우면 되기 때문이다.

- **정답 데이터:** 컬프 공통 SOP 매트릭스 107건 (정기 22, 시험 단계 37, 수시 42, 만료 6). 다만 이 표도 AI가 만든 것이라, 정답으로 쓰기 전에 실무자가 전수 검수해야 한다. 검수하면서 기한 규칙을 앞 절의 JSON 형식으로 바꾼다. 검수된 107건은 기본 템플릿이기도 하므로, 컬프 SOP로 재현율을 재면 자기 자신을 맞히는 시험이 된다. 의미 있는 평가는 두 번째 SOP 세트에서만 나온다.
- **매칭:** 추출 결과와 정답을 근거 조항 + 서식 코드로 자동 매칭하고, 애매한 쌍만 사람이 판정한다.

| 지표 | 정의 | 목표 (제안) |
| --- | --- | --- |
| 재현율 | 정답 의무 중 매칭된 비율 | 95% 이상 |
| 정밀도 | 추출 결과 중 정답에 매칭된 비율 | 참고 (낮아도 검토에서 제거 가능) |
| 기한 규칙 정확도 | 매칭된 의무 중 기한 종류·값이 맞는 비율 | 90% 이상 |
| 서식·근거 정확도 | 서식 코드와 근거 조항이 맞는 비율 | 90% 이상 |
| 플래그 탐지율 | 검토 메모 11건 중 SOP 내부에서 잡을 수 있는 항목을 플래그로 잡은 비율 | 참고 |

목표치는 제안이다. 첫 측정 후 다시 정한다.

- **평가 자동화:** 파이프라인을 바꿀 때마다 같은 스크립트로 돌려 지표와 놓친 항목 목록을 엑셀로 낸다.
- **과적합 주의:** 컬프 SOP에만 맞춘 키워드·패턴은 다른 회사 SOP에서 무너질 수 있다. 두 번째 SOP 세트(컬프 DRG·DEV 지침서, 가능하면 다른 기관 것)로 따로 검증한다.

## 기술 스택, 진행 단계, 위험

추천 구성은 서버 없는 정적 웹앱이다. 파싱·규칙 적용·저장이 모두 사용자 브라우저 안에서 일어나므로 운영비가 없고, SOP가 회사 PC 밖으로 나가지 않는다.

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 앱 | React + TypeScript (Vite), 정적 빌드 | 서버 없이 동작 |
| 배포 | GitHub Pages | 무료 호스팅 |
| 저장 | IndexedDB (Dexie) + File System Access API 파일 자동 저장 | 브라우저 내 저장 + PC·공유 폴더 파일 |
| 설치·오프라인 | PWA (vite-plugin-pwa) | 설치 권한 없이 아이콘 실행, 오프라인 동작 |
| 공유·백업 | 데이터 파일 공유 폴더 저장, JSON 내보내기·가져오기 | 서버 없이 회사 버전 공유 |
| 파싱 | JSZip(HWPX·DOCX), pdf.js(PDF) | 브라우저에서 처리 |
| 규칙 | JSON 설정 파일 + 정규식 | 코드 수정 없이 패턴 추가 |
| 기한 계산 | rrule.js, date-fns + 한국 공휴일 표 | 반복 규칙, 근무일 계산 |
| 캘린더·알림 | iCal(.ics, VALARM 포함) 내보내기, 구글·Outlook 웹 일정 추가 링크 | 서버 없이 캘린더 알림 사용 |
| 평가 | Node 스크립트 (같은 규칙 코드 사용) | 화면 없이 재현율 측정 |

대가: 여러 사람이 같은 데이터를 실시간으로 함께 편집할 수 없고, 앱이 직접 알람을 보내지 못한다. 데이터는 파일 자동 저장으로 지키고 알람은 캘린더에 맡긴다. 공동 사용이나 메일·메신저 알림 요구가 실제로 나오면 서버(또는 설치형 프로그램)를 다시 검토한다.

### 진행 단계

날짜는 아직 정하지 않았다. 각 단계는 앞 단계의 완료 조건을 만족해야 시작한다.

1. **정답 데이터 = 기본 템플릿 확정:** 107건 검수, 기한 규칙 JSON 변환, 항목별 매칭 키워드 작성. 완료 조건: 검수된 템플릿 파일.
2. **파서 + 규칙 매칭 + 평가 스크립트 (화면 없이):** 완료 조건: 두 번째 SOP 세트에서 재현율 목표 달성. 미달이면 화면 개발로 넘어가지 않는다.
3. **검토·확정 화면:** 완료 조건: 컬프 회사 버전 v1 확정.
4. **이벤트 안내, 시험 체크리스트, 캘린더 연동, 이행 기록, 파일 저장·PWA:** 완료 조건: 실제 시험 1건을 도구로 따라가 보고, 캘린더 알림을 받아 이행 기록까지 남긴다.
5. **개정 비교, 배포:** 완료 조건: GitHub Pages에서 다른 기관이 설치 없이 쓸 수 있음.

### 위험과 대응

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| 매칭 누락·오류 | 있는 의무를 없다고 믿게 됨 | 근거 원문 대조 검토, 미연결 템플릿 항목 경고 |

| 목록 노후화 | 개정 후 틀린 안내 | 개정 비교, 현행 SOP와 버전 불일치 시 경고 |
| 브라우저 데이터 삭제 | 확정 버전·이행 기록 유실 | 데이터 파일 자동 저장, 파일 미지정 시 첫 화면 경고 |
| 캘린더에 넣지 않은 일정 | 알람 없이 기한 경과 | 앱 첫 화면에 "캘린더 미등록" 표시, 이벤트 입력 직후 추가 버튼 노출 |
| 공유 폴더 동시 저장 | 한쪽 변경 덮어씀 | 열 때·저장 때 최근 저장자 확인 후 경고 |
| HWP 구버전 | 파싱 실패 | HWPX나 PDF로 저장해 올리도록 안내 |
| 책임 소재 | 누락으로 인한 분쟁 | SOP 원문 우선 고지, 확정자 기록 |

### 열린 질문

- [ ] 두 번째 검증용 SOP 세트를 어디서 확보할지 (다른 실시기관 SOP가 가장 좋고, 없으면 컬프 DRG·DEV)
